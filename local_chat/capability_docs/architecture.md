# معماری قابلیت‌ها

رجیستری قابلیت‌ها بیرون از prompt مدل نگهداری می‌شود. هر قابلیت با `register_capability` به پیاده‌سازی واقعی متصل می‌شود و مستندات کامل آن فقط در صورت درخواست خوانده می‌شود.

## مسیر درخواست

- پیام عادی مستقیماً به مسیر چت محلی می‌رود؛ برای هر پیام درخواست شبکه‌ای جداگانهٔ کشف قابلیت ارسال نمی‌شود.
- جست‌وجوی وب با دکمهٔ دستی یا تشخیص محلی عبارت‌های آشکارا روزآمد فعال می‌شود.
- فهرست قابلیت‌ها و مستندات فقط برای نمایش یا درخواست صریح از API خوانده می‌شوند.
- حافظهٔ بلندمدت در SQLite محلی نگهداری می‌شود و فقط با عبارت‌های صریح کاربر ذخیره یا حذف می‌شود.

رجیستری، قابلیت جدیدی به مدل نصب نمی‌کند و به‌تنهایی مجوز اجرای کد یا ابزار دلخواه نمی‌دهد. هر قابلیت اجرایی به پیاده‌سازی امن سمت برنامه و تست مستقل نیاز دارد.
